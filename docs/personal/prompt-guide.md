# 프롬프트 작성 가이드 (`docs/personal/prompt-guide.md`)

> 이 프로젝트에서 AI에게 작업을 요청할 때 참고하는 문서입니다. 사람이 읽는 용도이며, AI 작업 규칙은 `AGENTS.md`가 기준입니다.
> 작성: 2026-11-25 (프로젝트 초기 세션 회고 기반)

---

## 1. 기본 공식

> **[무엇을] + [어디에/어느 범위] + [기준] + [하지 말 것] + [끝났다고 볼 조건]**

다섯 개를 다 쓸 필요는 없습니다. **범위**와 **기준**만 있어도 결과가 크게 안정됩니다.

```text
Checkbox 컴포넌트에 size="sm"을 추가해줘.        ← 무엇을
Checkbox.tsx, 가이드, Checkbox.md만 고쳐.         ← 범위
크기는 Input의 sm과 높이를 맞춰.                   ← 기준
다른 컴포넌트는 건드리지 마.                       ← 하지 말 것
가이드에서 sm이 보이고 린트·빌드 통과하면 끝.       ← 끝 조건
```

**한 줄 요약:** "어디까지"를 적으면 절반이 해결되고, "어떻게 확인할지"를 적으면 나머지가 해결됩니다.

## 2. 상황별 요청 방법

| # | 방법 | 예시 |
| --- | --- | --- |
| 1 | **범위를 꼭 적기** (가장 중요). 빠지면 AI는 보통 넓게 해석합니다 | "이 파일만" / "이 컴포넌트만" / "앞으로 전부" |
| 2 | **알려 주기와 바꾸라고 하기를 구분** | 알려 주기: "참고로 A는 원래 B야" / 바꾸기: "A를 B로 **바꿔줘**" |
| 3 | **문서만인지, 코드도인지** 적기 | "문서만 고쳐" / "코드도 같이" / "고치지 말고 문제만 적어줘" |
| 4 | **처음엔 하나만 시험** | "Icon.md 하나만 먼저 해 봐. 괜찮으면 나머지도 할게" |
| 5 | **기준 예시를 가리키기** (긴 설명보다 정확) | "Button.md처럼 써줘" / "이번에 한 방식 그대로 Select에도" |
| 6 | **판단을 맡길 때는 맡긴다고 말하기** | "어떻게 나눌지는 네가 정하고 이유만 알려줘" |
| 7 | **확인 방법을 정해 주기** | "화면에서 직접 확인까지 해줘" / "빌드만 통과하면 돼" |

## 3. 바로 쓰는 요청 틀

```text
[컴포넌트 고치기]
{컴포넌트}의 {무엇}을 {어떻게} 바꿔줘.
코드·가이드·docs/components/{이름}.md 함께. 다른 컴포넌트는 그대로.
끝나면 화면 확인하고 린트·빌드 결과 알려줘.

[문서만 정리]
docs/components/{이름}.md만 고쳐줘. 코드는 건드리지 마.
{바꿀 내용}

[조사만]
{대상}에서 {문제 종류}를 찾아서 목록만 줘. 고치지는 마.

[시험해 보기]
{대상} 하나만 {작업} 해 봐. 규칙이나 다른 파일에는 반영하지 마.

[되돌리기]
{파일}을 {언제} 상태로 되돌려줘. 그때 같이 바꾼 것도 전부.

[페이지 만들기]
src/publish/pages/{경로}.tsx에 {페이지명} 페이지를 만들어줘.
쓰는 컴포넌트: {목록}. docs/components의 규칙을 따르고 publishing.ts에 등록해줘.
목업 데이터로 하고, 화면 확인까지.
```

## 4. 실제 사례 (2026-11-25 세션)

### 잘 된 요청

| 요청 | 잘 된 이유 |
| --- | --- |
| "AGENTS.md에 규칙 추가해줘: className은 배치·간격에만, 간격은 gap-2·4·6 세 단계만" | 무엇을·어디에·기준이 한 문장에 다 있어 질문 없이 끝남 |
| "Button, Input을 docs/components/{이름}.md로 짧게. Props, variant, 접근성, 하면 안 되는 것만" | 파일 위치와 항목이 정해져 형식이 한 번에 맞음. 이후 "이런 식으로 10개, abc순"도 쉽게 확장 |
| "button.md 기본값을 button으로" | 짧지만 정확해서 코드까지 함께 고칠 수 있었음 |
| "나중에" | 미룬 일을 `tasks.md`에 기록해 잊지 않게 됨. 판단만 줘도 충분함 |

### AI 쪽에서 아쉬웠던 점

- 범위가 불분명한 요청(축약)을 받았을 때 **범위를 먼저 묻지 않고** 규칙·기억에까지 반영함 → 되돌리기 쉬운 작업만 하고 범위를 확인해야 함
- 한 번에 많은 문서를 바꿔 사람이 확인하기 어려웠음 → 큰 변경은 나눠서 보고
