> 출근 후 확인하고 협의할 항목은 `work-checklist.md`에 있습니다.

## 1. 내 역할

- **퍼블 PL**
- 퍼블리싱도 바이브 코딩(SSOT 기반 AI 작업)으로 진행. 손 코딩은 AI가 정 안 될 때만
- 손으로 치는 일보다 **AI 결과를 읽고 판단하는 능력**이 중요함

## 2. 팀별 상황

| 팀 | 상황 |
| --- | --- |
| 기획 | 현업과 요건 정리, IA 설계 중 |
| 디자인 | 외부망에서 피그마 작업 |
| 보안 | 외부망 결과물을 심사 후 내부망으로 반입, 내부에서 다시 동기화 |
| 내부 AI | 내부망에 설치. **md 규칙 문서를 읽고 그 기반으로 작업** |
| 백엔드 | 팀장과 데이터 전달 방식 회의 예정 (폼, 컴포넌트 데이터 처리, 오너십) |

## 3. 지금까지 정리된 생각 (2026-11-25)

| 주제 | 내용 |
| --- | --- |
| 피그마 추출 | 미정. Claude Code만으로는 무리 → **Dev Mode + MCP** 검토 중. MCP는 외부망에서만 돌아가므로 이관은 여전히 필요 |
| 이관 범위 | **컴포넌트만** div 코드로 받아 내부에서 우리 규칙대로 React로 변환. 페이지는 그 컴포넌트로 내부에서 작성 |
| 페이지 자료 | 캡처본 정도만 반입. 명세는 오지 않을 가능성이 큼 → SSOT가 명세 역할을 대신함 |
| 디자이너 AI 코드 품질 | 알 수 없음 → 반입 전 통과 기준 협의 필요 |
| 컴포넌트 문서 구조 | 팀별 분리(`_기획`, `_디자인`, `_dev`)는 관리할 곳이 늘어남. 대안은 한 파일에 칸 고정. **이관 방식이 정해진 뒤 대응** |
| 백엔드 협의 | 데이터 자체가 아니라 **화면과 데이터가 만나는 경계**를 정하는 회의. 안건은 역할, Props 모양, 폼 규칙, 화면 상태 |
| 컴포넌트 단계 | 아토믹 대신 **"업무를 아는가"**로 나누기: 기본 컴포넌트 / 업무 컴포넌트 / 페이지. 업무 컴포넌트만 백엔드와 데이터 협의 |
